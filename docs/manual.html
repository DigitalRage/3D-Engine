Introduction

This is a browser-based 3D editor built for a flat, anime / toon look. It includes mesh modeling, multi-scene management, prefabs, skeletal animation, and a simple game runtime so the same content can be played without the editor UI.

Rendering uses flat shading with optional textures. Directional raytraced hard shadows reinforce the cel-shaded aesthetic (automatically scaled back on very large scenes so the editor stays interactive).

Quick start

  1. Serve the project folder with any static server (npx serve . or python -m http.server).
  2. Open the page in a modern browser with WebGL.
  3. A default cube is present. Use the toolbar / hierarchy / inspector panels.
  4. Press P or F5 to enter Play mode; Esc returns to the editor.
If the UI looks missing, ensure you are not still in Play mode (UI is dimmed) and that the page was opened via http://, not file://.

Selection modes

Use keys 1–4 or the UI pick-mode control. Face/edge/vertex picks support additive selection with Shift/Ctrl. Many modeling operators act on the current face selection set.

Modeling tools

Available from the UI and (where bound) shortcuts: extrude, inset, bevel, loop cut, bridge, fill, grid fill, dissolve, split, separate, triangulate, quad rebuild, knife, add/merge vertices, merge coplanar faces, recalculate/flip normals.

Most face operators are undoable as a single mesh command.

Transforms & gizmos

Select Move, Rotate, or Scale, then drag axis handles. World/local space and snap steps are available in the UI. Axis constraints can be toggled with X/Y/Z during a drag.

Transform updates are optimized: model matrices are cached and full scene asset rebuilds are deferred so dragging one object among thousands stays responsive.

Scenes & prefabs

Create, save, duplicate, and switch scenes via the scene panel. Sub-scenes can stream in/out. Prefabs support nested prefabs, instantiate, update, and revert overrides.

Bones & animation

Add bones to a mesh skeleton, key position/rotation/scale on the animation clip, seek and play from the animation workspace. Skinning uses vertex weights on shared topology.

Anime / toon shading

Materials default toward toon shading. The directional light exposes intensity, threshold, light color, and shade color — the classic two-tone cel look. Face colors and textures multiply on top of the lighting.

Raytraced shadows

In Anime render mode, a BVH-accelerated raytracer casts hard shadows from the directional light onto toon-shaded faces. This is intentional for a clean anime silhouette, not soft photoreal contact shadows.

On scenes with more than ~800 meshes, full per-face raytraced shadows are automatically disabled so the frame rate stays usable. Toon lighting still applies; only the ray-shadow term is skipped.

Render modes

  • Anime — toon + optional ray shadows (default aesthetic)
  • Material — textured/lit without full toon treatment
  • Solid — flat colors, no textures
  • Wireframe — edges only (always draws every mesh; useful to verify object counts)

Large scenes (1000+ objects)

Use Add batch for primitives. Creation yields to the browser so the UI stays responsive. The renderer uses:

  • Frustum culling (when many objects exist)
  • GPU instancing for identical opaque meshes (chunked in groups of 512 to avoid GPU limits)
  • Cached model matrices
  • Deferred asset registration after mass add
If only a few objects show in Anime/Solid but all show in Wireframe, switch render mode once or orbit the camera — frustum and instance batches will refresh. Prefer Wireframe to confirm the full set was created.

Performance tips

  • Prefer identical primitives (same type/scale) so instancing can group them.
  • Avoid selecting thousands of meshes at once (hierarchy refresh cost).
  • Keep unique geometry counts down when possible; share shapes via duplication.
  • For game prototypes, use Play mode so editor overlays and gizmo work stop.

Play mode

Press P or F5. The runtime takes over the loop, dims the editor UI, enables a fly camera, and can attach simple physics to cubes/spheres.

  • WASD — move
  • Q/E — down / up
  • Mouse drag (RMB or Shift+LMB) — look
  • Esc — back to editor

Runtime API

import { GameRuntime } from './engine/runtime.js';

const runtime = new GameRuntime(renderer, scene, camera);
runtime.enableFlyCamera(5);
runtime.physics.addBody(mesh, { gravity: -12, radius: 0.5 });
runtime.addScript('logic', (dt, rt) => { /* ... */ });
runtime.play();

Import / export

OBJ is the primary geometry exchange format. Export OBJ + MTL writes each mesh as its own named o object and bakes its transform into the vertex positions. The companion MTL stores flat diffuse colors, emission, opacity, roughness, and metallic values. Import OBJ Scene accepts an OBJ plus an optional MTL; every named OBJ object becomes a separate mesh. Legacy JSON scene files remain supported for engine-specific metadata such as lights, audio, prefabs, and animation data.

OGG Audio

The Audio panel reads assets/sound/index.json. Put OGG files in assets/sound/ and run node tools/build-sound-manifest.mjs to make them selectable.

Audio supports background music, looping, crossfades, previews, four mixer buses, queue/overlap/replace action cues, cooldowns, polyphony limits, playback-rate variation, and optional 3D spatial positioning.

In play mode, use rt.playSound('sound-id'), rt.queueSound('sound-id'), or rt.triggerAudioAction('player.jump', { position: [x, y, z] }).

Rendering Performance

The renderer keeps the depth buffer enabled so nearer surfaces correctly occlude farther surfaces. Opaque geometry is additionally sorted front-to-back and back-face culled in hardware unless a material is marked double-sided. Frustum tests use cached local bounding spheres transformed into world space, which is cheaper and more correct for off-center meshes.
